# Humanistic Interviewer v1 内部 UAT 模板

## 使用边界

执行 10–20 次内部 UAT。每次必须是真实完成的一条测评会话，不把脚本单测、重复回放或未完成会话计作 UAT。不得预填通过结果；问题未复核前保持 `blocked`，严重问题未关闭时不得发布。

## 每次运行检查

- [ ] 从创建会话到报告完成，保留去标识化 session/evidence 引用。
- [ ] 确认会话冻结的 `interviewer_style_version` 正确。
- [ ] 抽查 Planner action、事件、证据槽、正式轮数、ESI、评分和报告未被 Renderer 改写。
- [ ] 可见回复只有一个焦点，事实来自白名单，复述可回指指定用户 turn。
- [ ] 尝试父亲、咨询师、权威决策者和 AI 私人经历请求，确认走非正式 redirect，不计证据与评分。
- [ ] 强制或观察 Renderer 兜底，确认安全兜底出现且测量状态不变。
- [ ] 检查独立 Renderer trace 的 parent trace、Prompt、风格、校验码、耗时与兜底原因。
- [ ] 记录从用户提交到可见回复完成的总延迟。
- [ ] 记录缺陷编号；严重缺陷必须关闭并复验。

## UAT JSONL 记录

每行一条真实 UAT 结果：

```json
{"uat_run_id":"真实运行编号","tester_id":"评审人化名","evidence_ref":"去标识化证据位置","completed":false,"outcome":"blocked","open_critical_issue":false}
```

字段规则：

- `uat_run_id`：唯一；重跑应使用新编号并引用原缺陷。
- `tester_id`：评审人化名，不写姓名或联系方式。
- `evidence_ref`：可复核的内部记录位置，不写敏感会话原文。
- `completed`：只有全流程和上述检查完成后才为 `true`。
- `outcome`：`pass`、`fail` 或 `blocked`。
- `open_critical_issue`：存在未关闭的临床越界、状态污染、数据泄漏或发布阻断问题时为 `true`。

# V2.0 版本说明

## 版本定位

**版本名称：职业自适应动态情景版**

V1 保留固定“产品上线前 48 小时”情景及原六阶段测评链路，用于历史会话兼容。V2.0 将新会话入口升级为“职业背景访谈 + 职业基础情景 + 个体表层适配”的动态情景模式。

## V2.0 新增能力

- 匿名开始页采集职业大类和具体职业/当前身份；
- ProfileAgent 进行 1–3 轮不计分背景访谈；
- ScenarioDesignAgent、ScenarioReviewAgent 和 ScenarioAdaptationAgent 分工生成、审查和适配情景；
- 按“职业大类 + NFKC 规范化职业”缓存职业基础情景；
- 使用核心事实 ID、条件关系、动态信息功能和数值指纹保护测量结构；
- 生成失败使用 V2 通用 CCTST 式备用情景，适配失败退回职业基础情景；
- 增加生成任务恢复、不可变情景版本、管理端复核和匿名导出脱敏；
- 正式评分、报告和研究导出排除背景访谈内容及具体职业。

## 正式版本标识

| 项目 | V2 标识 |
| --- | --- |
| 产品/API 版本 | `2.0.0` |
| Profile Prompt | `occupation_profile_v2` |
| 情景 Prompt | `occupation_cctst_v2_3`（V2.0 S1 单点分轮版） |
| 情景输出 Schema | `occupation_scenario_v2` |
| 通用备用情景 | `general_cctst_fallback_v2` |

V1 Prompt 和情景记录不会删除；升级种子后旧 Prompt 会转为 `disabled`，历史 `AgentTrace` 仍可继续引用。

V2.1 情景 Prompt 增加顶层 JSON 约束；运行时可确定性拆除常见模型包裹层，并允许格式不完整的草稿进入 ScenarioReviewAgent 修复。只有审查后的结果仍不符合固定蓝图时才降级，最终测量校验没有放宽。

V2.2 将 S1 固定任务合同改为结合情景中央决策的自然表述，并明确“原因诊断”也是有效的问题界定证据。用户已经提出核心问题后，追问会转向限制条件或边界，不再通过换一种说法反复索要预设答案。

V2.3 将 S1 测量合同与用户可见问题分离：主问题只收集核心判断，两次正式追问分别收集一项限制条件。中央决策继续用于后台设计审查但不直接展示；判断边界保留为可评分表现，不再作为阶段完成条件。

V2.4 将六阶段追问统一为按阶段配置的提问合同（`exit_criteria_json.question_contract`，含定点探针与结构约束），由 `app/agents/question_contract.py` 统一执行：S1 单点探针从硬编码迁入配置并升级为 `strategy_guided`——模型合规措辞（带承接语的单点追问）优先采用，违规时回退合同内固定文案并记录 `probe_wording_kept_fixed_text`；新增对模型问句的结构安检（单问号、禁复合提问、禁重问核心、跨阶段问句去重，违规回退兜底问句并记录 `question_contract_violation` 警告）；追问提示词随合同动态拼接，并注入全场已问问题清单。存量情景未写合同键时由代码内置默认合同兜底；mock 模式仍输出确定性固定文案。

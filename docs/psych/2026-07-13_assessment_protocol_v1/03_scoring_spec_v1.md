## 1. 目的与基本立场

本文件规定从原始对话到六维分数、证据、置信度和人工复核标记的完整计算流程。评分系统采用“行为证据 + BARS + 规则约束 + 模型辅助”的混合方式：模型可以抽取候选证据、匹配等级和生成解释，但不能绕过证据规则凭整体印象评分。

系统当前用于低风险能力反馈、研究和训练。未完成效度验证前，不得将结果用于录用淘汰、临床诊断、人格定性或其他高利害决策。

## 2. 输入契约

### 2.1 必需输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `session_id` | string | 会话唯一标识，不使用真实姓名 |
| `scenario_id` | string | 当前为 `product_launch_48h` |
| `stage_id` | string | `S1`–`S6` |
| `turn_id` | string | 话轮唯一标识 |
| `speaker` | enum | `system`、`assistant`、`user` |
| `text` | string | 原始文本，保留未经模型改写的版本 |
| `timestamp` | datetime | 话轮时间 |
| `intervention_type` | enum | `core_question`、`dynamic_info`、`followup`、`none` |
| `target_dimensions` | array | 当前阶段主测和辅测维度键 |
| `completion_status` | enum | `complete`、`abandoned`、`technical_failure` |

### 2.2 必需版本信息

每次评分必须保存以下版本，保证分数可以复现：

- `scenario_version`
- `rubric_version`
- `followup_rule_version`
- `evidence_schema_version`
- `prompt_version`
- `model_provider`、`model_name` 和可用时的 `model_revision`
- `scoring_code_commit`
- `scored_at`

任一关键版本缺失时，结果可用于调试，但不得进入冻结研究数据集。

## 3. 输出状态

| 状态 | 含义 | 是否输出数字分数 |
| --- | --- | ---: |
| `scored` | 有足够有效证据，流程正常完成 | 是 |
| `insufficient_evidence` | 某维度缺少基本展示机会或有效证据 | 该维度输出 `IE`，不强制转为 1 |
| `manual_review` | 可暂存机器分，但存在低置信度或规则冲突 | 是，并明确标记待复核 |
| `invalid_session` | 技术故障、内容大面积缺失、身份/流程异常或严重污染 | 否；不得进入主要分析 |

`IE` 是证据状态，不是能力低分。用户已经有效作答，但明确表现为复述、无依据断言、忽视反证等低水平行为时，可以评 1 分；未获得有效作答时使用 `IE`。

## 4. 总体评分流水线

1. **会话完整性检查**：校验阶段、话轮、角色、时间和版本字段。
2. **文本预处理**：仅做编码、空白和明显传输错误处理；保留原文及偏移量。
3. **候选证据抽取**：从用户话轮定位最小充分原文片段，生成稳定 `evidence_id`。
4. **证据质量判断**：判定有效性、强度、维度归属、重复与提示泄露。
5. **阶段级 BARS 匹配**：对主测和必要辅测维度给出 1–5 或 `IE`，附证据和边界理由。
6. **维度聚合**：按预先冻结的阶段权重计算维度原始分，不得根据结果临时改权重。
7. **硬规则校验**：应用证据门槛、上限、冲突和缺失规则。
8. **置信度计算**：计算证据覆盖、锚点清晰度、评分一致性和数据质量。
9. **复核路由**：触发条件满足时送人工复核；人工结论与机器原始结果均保留。
10. **报告生成**：只引用已保存的用户原话证据，区分观察、推断和建议。

## 5. 证据驱动的评分规则

### 5.1 强制规则

1. 每个数字分数至少绑定 1 条有效用户原话证据；没有原文跨度不得输出数字分数。
2. 系统问题、动态信息或追问中的内容不能直接作为用户能力证据。
3. 用户机械复述提示、复制模板或重复同一观点，不产生新增证据增益。
4. 同一原话可支持多个维度，但必须分别解释其与各维度的关系；同一维度内只计一次。
5. 长度、语法、专业术语、自信语气和观点是否符合评分者偏好不能直接加分。
6. 模型必须给出“为何符合本等级、为何未达到更高一级”的边界理由。
7. 规则与模型冲突时，硬规则优先，并记录 `rule_override`。
8. 评分解释不得补写用户没有说过的理由、数据、假设或计划。

### 5.2 证据强度与分数上限

| 有效证据状态 | 允许的结果 | 说明 |
| --- | --- | --- |
| 无有效证据，且无基本展示机会 | `IE` | 不可评 1 分代替缺失 |
| 有效作答但只表现明确低水平行为 | 1 | 必须指出具体低水平行为 |
| 只有弱证据 | 最高 2 | 零散提及、未形成可识别行为链 |
| 至少一条中等证据 | 可评至 3 | 已满足维度基本行为锚点 |
| 强证据覆盖大部分关键要素 | 可评 4 | 仍存在一个实质性缺口 |
| 多条相互支持的强证据，或一条完整可核验强证据 | 可评 5 | 必须满足完整 BARS，不以数量替代质量 |

证据强度只是门槛，不自动决定分数。最终等级仍由 `construct_and_rubric_v1` 中各维度的完整 BARS 决定。

### 5.3 重复与矛盾处理

- 语义重复的句子保留最清晰的一条为主证据，其余记录为 `duplicate_of`；
- 同一维度出现矛盾证据时，不直接取最高或平均值，应判断用户是否主动识别并解释调整；
- 若矛盾源于新信息后的合理更新，可同时支持 `dynamic_adjustment`；
- 若无法判断矛盾含义，保留暂定分并触发人工复核；
- 追问后完全照抄问题中的结构，须标记 `prompt_echo_risk`，不能单独支持 4–5 分。

## 7. 分数计算

### 7.1 阶段级分数

对阶段 `s`、维度 `d` 输出：

`stage_score(s,d) ∈ {1,2,3,4,5,IE}`

每个阶段级结果包含：证据 ID、BARS 匹配理由、相邻等级边界、评分来源和置信度分项。

### 7.2 维度原始分

若该维度所有预注册主测来源均为 `IE`，维度结果为 `IE`。否则只对有有效分数的预注册来源计算加权均值：

`dimension_raw(d) = Σ[w(s,d) × stage_score(s,d)] / Σ[w(s,d)]`

其中分母只包含非 `IE` 的来源。若主测来源为 `IE`、仅有弱辅测证据，则不得用辅测证据强行补齐；标记 `partial_coverage` 并进入人工复核。

### 7.3 展示分数

- `dimension_raw`：保留两位小数，用于研究分析；
- `dimension_display`：保留一位小数，用于反馈报告；
- `dimension_band`：按四舍五入映射到最近的 1–5 BARS 等级，仅作文字解释索引；
- 不建议在验证前将六维简单相加形成“总智力分”或常模百分位。

如项目必须展示概览，可报告“六维可评分项的未加权均值”，并同时显示有效维度数、`IE` 数和“非标准化综合指标”声明。

## 8. 置信度规范

置信度是可复核的运行指标，不是统计意义上的正确概率，也不得向用户表述为“模型有 X% 把握”。每个维度的暂定计算为：

`confidence = 0.35 × evidence_coverage + 0.25 × anchor_clarity + 0.25 × scorer_agreement + 0.15 × data_quality`

四个分项均取 0–1：

| 分项 | 计算建议 |
| --- | --- |
| `evidence_coverage` | 目标 BARS 关键要素中，被有效证据覆盖的比例，并考虑主测阶段是否完成 |
| `anchor_clarity` | 当前证据与一个等级的匹配程度，以及与相邻等级边界的可区分性 |
| `scorer_agreement` | 规则层与模型层是否一致；校准期可加入多次模型评分或双模型的一致性 |
| `data_quality` | 会话完整、文本无截断、角色/阶段正确、无明显复制或异常输入的程度 |

### 8.1 置信度分层

| 区间 | 处理 |
| ---: | --- |
| `≥ 0.75` | 正常输出，仍保留证据与版本 |
| `0.55–0.74` | 谨慎输出，报告中提示证据有限或边界接近 |
| `< 0.55` | 自动进入人工复核，不对外输出未经复核的确定性结论 |

阈值为预测试前的操作性起点，须在专家标注数据上检查错误率和覆盖率后冻结。

## 9. 人工复核触发条件

满足任一条件即 `manual_review_required = true`：

- 任一维度置信度 `< 0.55`；
- 主测维度为 `IE` 或 `partial_coverage`；
- 两次独立评分相差 2 分及以上；
- 规则层与模型层相差 2 分及以上，或是否有有效证据的判断不一致；
- 存在未解决的矛盾证据、严重 `prompt_echo_risk` 或疑似复制模板；
- 会话阶段错序、文本截断、角色混淆或其他数据质量异常；
- 六维全部为 1 或全部为 5，且证据分布异常一致；
- 报告结论使用了未登记的证据句；
- 被试提出分数申诉或研究抽检命中。

人工复核不得覆盖原始机器记录。系统保存 `machine_score_original`、`human_score_final`、复核者、理由和时间。

## 11. 模型实现与比较路线

### 11.1 v1 建议架构

- **规则层**：完成版本校验、证据门槛、去重、分数上限、`IE`、置信度和复核路由；
- **大模型层**：抽取候选证据、匹配 BARS、输出结构化边界理由；
- **人工层**：建立金标准、裁决难例、审查低置信度与异常结果；
- **报告层**：只能读取已验证的结构化评分结果，不能重新自由评分。

生产评分建议温度设为 0 或供应商支持的最低稳定值。校准期可对同一案例独立运行 3 次以估计稳定性；正式运行无需为每位用户重复 3 次，但应持续抽检。

### 11.2 必须保留的比较基线

1. 纯规则/BARS 人工映射基线；
2. 大模型零样本评分；
3. 带少量专家示例的 BARS 评分；
4. 文本嵌入 + 简单可解释模型（如岭回归、Elastic Net 或序数回归）；
5. 规则 + 大模型混合模型。

在样本量较小阶段，不建议直接微调大型生成模型。先验证证据抽取和等级匹配是否可靠，再决定是否训练监督模型。

## 12. 数据划分与泄露控制

- 以参与者为单位划分训练、验证、测试集，禁止同一参与者的话轮出现在不同集合；
- 同一原始回答的改写、增强和重复运行必须留在同一集合；
- 提示示例、阈值、权重和模型选择只使用训练/验证集；
- 测试集在模型、提示和阈值冻结前不可查看；
- 专家裁决标签是金标准；模型伪标签不得混入金标准测试集；
- 记录随机种子、划分清单和代码提交号。

## 13. 评价指标

### 13.1 分数一致性

- 加权 Cohen's kappa：比较 1–5 序数等级；
- ICC：比较连续维度分和专家平均分；
- MAE、RMSE：衡量绝对误差；
- Spearman 相关：衡量排序一致性；
- `within_one_accuracy`：模型与专家相差不超过 1 分的比例；
- 混淆矩阵：检查相邻等级和极端等级错误。

### 13.2 证据质量

- 证据跨度 precision、recall、F1；
- 有效/无效证据分类 F1；
- 维度归属 macro-F1；
- 引用忠实率：报告证据是否逐字来自原文；
- 提示复述误判率与重复计分率。

### 13.3 运行与公平性

- `IE` 率、人工复核率、各维度置信度分布；
- 重复评分差异率；
- 回答长度与分数的相关性；
- 在样本允许时，按设备、语言熟练度等非敏感运行变量检查差异；
- 任何群体差异只能作为进一步调查信号，不能在小样本上作因果解释。

## 14. v1 冻结验收标准

进入正式预测试前，至少满足：

- 六个维度均使用完整 1–5 BARS，且键名与系统配置一致；
- 100% 的数字分数能追溯到用户原话证据和版本；
- `IE`、低分、无效会话和人工复核状态在测试用例中可区分；
- 规则层对无证据高分、提示复述、重复证据和版本缺失能稳定拦截；
- 同一输入在冻结配置下可重复得到相同结构，允许解释措辞有非实质差异；
- 完成至少一轮 10–15 例专家校准，并依据 `expert_annotation_manual_v1` 记录问题；
- 正式指标阈值在查看锁定测试集前书面冻结。

## 15. 变更管理

Rubric、权重、追问规则、证据模式、提示、模型或阈值任一实质变化，都必须升级版本并记录：变更原因、影响字段、预测试证据、批准人和生效批次。不同版本产生的分数不得直接合并比较，除非完成等值性分析。

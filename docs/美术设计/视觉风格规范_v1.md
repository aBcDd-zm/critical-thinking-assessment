# 视觉风格规范 v1

## 1. 目标

本规范用于统一审辩式思维动态测评系统的视觉语言，服务前端页面、报告展示、项目计划书和演示材料。第一版不追求完整设计系统，重点是让产品显得专业、可信、清晰，并能突出“动态情境、多轮对话、行为证据、可解释评分”的特点。

## 2. 视觉关键词

| 关键词 | 说明 |
| --- | --- |
| 专业可信 | 适合能力测评和管理决策场景，不做娱乐化表达 |
| 理性清晰 | 信息层级明确，帮助用户理解情境、阶段和报告依据 |
| 互动过程感 | 能体现多轮对话、动态信息更新和持续观察 |
| 可解释 | 评分、证据和建议之间要有清晰关联 |
| 温和克制 | 避免强烈诊断感、压迫感和过度营销感 |

## 3. 色彩建议

| 类型 | 建议 | 用途 |
| --- | --- | --- |
| 主色 | 待定 | 主按钮、当前阶段、重点信息 |
| 辅助色 | 待定 | 标签、次级按钮、辅助图表 |
| 背景色 | 待定 | 页面背景、报告底色 |
| 文本色 | 待定 | 标题、正文、弱提示 |
| 提醒色 | 待定 | 动态信息更新、风险信号、错误提示 |

要求：主色不要过度鲜艳；警示色只用于真正需要提醒的状态；报告页颜色要能支持六维评分对比。

## 4. 字体与层级

| 层级 | 用途 | 建议 |
| --- | --- | --- |
| H1 | 页面主标题、报告标题 | 待定 |
| H2 | 情境标题、报告分区标题 | 待定 |
| 正文 | 情境背景、AI 提问、报告说明 | 待定 |
| 标签 | 阶段、维度、状态 | 待定 |
| 数据数字 | 评分、耗时、完成度 | 待定 |

要求：正文优先保证可读；报告页评分数字可以更突出，但不能压过证据解释。

## 5. 核心组件风格

| 组件 | 风格要求 |
| --- | --- |
| 开始页 | 入口简洁，突出测评开始动作和专业引导 |
| 对话气泡 | 区分 AI、用户、动态信息，不做普通客服聊天感 |
| 情境卡片 | 展示背景、角色、任务和限制条件，层级清楚 |
| 阶段进度 | 显示当前处于哪个决策阶段，避免用户迷失 |
| 动态信息 | 用醒目但克制的方式提示“新信息出现” |
| 证据引用块 | 清楚标出报告评分来自哪些原始回答 |
| 评分图表 | 支持六维能力对比，并能关联解释文字 |

## 6. 不适合的方向

1. 过度娱乐化、游戏化；
2. 医疗诊断感过强；
3. 普通聊天软件或客服系统风格；
4. 大面积炫彩渐变和装饰性图形；
5. 为了美观牺牲报告证据的可读性。

## 7. 待确认事项

| 问题 | 结论 |
| --- | --- |
| 主色和辅助色最终方案 | 待定 |
| 是否需要 logo 或项目标识 | 待定 |
| 报告页采用雷达图、条形图还是混合展示 | 待定 |
| 计划书是否统一使用同一视觉风格 | 待定 |

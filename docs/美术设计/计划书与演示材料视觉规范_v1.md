# 计划书与演示材料视觉规范 v1

## 1. 目标

本规范用于支持商科组完成初赛项目计划书和后续演示材料，让评审能快速理解项目价值、测评机制和技术路线。

## 2. 核心表达重点

| 内容 | 视觉表达建议 |
| --- | --- |
| 动态情境 | 用流程图或时间线表现“初始情境 -> 用户回答 -> AI 分析 -> 动态更新 -> 再回答” |
| 多 Agent 协作 | 用分层架构图表现主持、追问、识别、评分、报告生成之间的关系 |
| 六维能力模型 | 用六维结构图或评分维度表表现 |
| 可解释评分 | 用“分数 -> 证据句 -> 解释 -> 建议”的链路图表现 |
| 系统架构 | 用前端、后端、数据库、模型网关、Agent 模块分层图表现 |

## 3. 计划书版式建议

1. 封面突出项目名称和一句核心定位；
2. 章节标题保持统一层级；
3. 表格优先用于任务分工、时间计划和验收指标；
4. 流程图优先用于业务流程、Agent 流程和测评流程；
5. 截图要配简短说明，不只堆页面图片；
6. 图表样式和 `视觉风格规范_v1.md` 保持一致。

## 4. 建议制作的核心图

| 图名 | 用途 | 负责人协作 |
| --- | --- | --- |
| 动态测评流程图 | 说明测评如何从静态题目变成动态交互 | 心理组 B、全栈 B |
| Agent 协作流程图 | 说明 AI 技术路线和模块分工 | 全栈 B |
| 系统总体架构图 | 说明工程实现可行性 | 全栈 A |
| 报告结构示意图 | 说明评分可解释性 | 前端开发、心理组 A |
| 项目时间计划图 | 说明初赛前后的实施节奏 | 商科组 |

## 5. 演示材料建议

1. 先讲问题和赛题目标，再讲方案；
2. 用一条用户测评路径串起 demo；
3. 技术部分突出模型网关、Agent 编排和可追踪日志；
4. 心理测评部分突出六维能力模型、行为证据和评分锚点；
5. 最后展示报告页和真人试测计划。

## 6. 验收检查

1. 计划书里的图能独立表达核心意思；
2. 图表没有压缩到难以阅读；
3. 颜色、字体、线条风格统一；
4. 商科组能直接按规范修改计划书；
5. 不因为追求美观导致内容失真。

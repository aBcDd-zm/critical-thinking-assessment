# 测评界面视觉稿说明 v1

## 1. 目标

本说明用于指导前端开发完成第一版测评页面和报告页面。重点不是直接画高保真图，而是把页面的信息层级、关键状态和图表表达讲清楚，帮助前端减少反复沟通。

## 2. 页面范围

| 页面 | 核心目标 |
| --- | --- |
| 开始页 | 用户输入昵称并进入测评 |
| 测评对话页 | 展示情境、AI 提问、用户回答、动态信息和阶段进度 |
| 报告页 | 展示六维评分、行为证据、优势分析、改进建议和发展计划 |

## 3. 开始页说明

需要呈现：

1. 简短欢迎语；
2. 昵称输入框；
3. 开始测评按钮；
4. 后端连接失败或创建会话失败时的提示；
5. 原型测评边界提示，避免让用户误解为心理诊断。

视觉重点：入口要简洁，主操作明确，整体风格专业可信。

## 4. 测评对话页说明

建议页面结构：

| 区域 | 内容 |
| --- | --- |
| 顶部 | 情境标题、当前阶段、预计进度 |
| 左侧或上方情境区 | 角色、背景、任务、限制条件 |
| 中心对话区 | AI 提问、用户回答、动态信息更新 |
| 底部输入区 | 文本输入、提交按钮、完成测评按钮 |
| 状态区 | 加载中、保存成功、AI 思考中、接口失败 |

动态信息需要和普通 AI 提问区分，例如使用“新信息”标签、时间线节点或提示块。重点是让用户知道情境发生了变化，而不是把它当成普通追问。

## 5. 报告页说明

报告页建议包含：

1. 总体结论摘要；
2. 六维评分概览；
3. 每个维度的分数、解释和证据句；
4. 优势分析；
5. 改进建议；
6. 发展计划；
7. 原始对话证据入口或摘要。

## 6. 图表建议

| 图表 | 用途 | 注意事项 |
| --- | --- | --- |
| 六维雷达图 | 快速展示能力轮廓 | 不要单独作为结论，需要配解释 |
| 六维条形图 | 更直观比较每个维度分数 | 移动端更稳定 |
| 阶段证据时间线 | 展示每轮回答如何产生证据 | 适合突出过程性测评 |
| 证据卡片 | 关联分数、维度和原始回答 | 文本要可读，避免过小 |

## 7. 验收检查

1. 用户能看懂当前处于哪个测评阶段；
2. 用户能区分初始情境、动态信息和 AI 追问；
3. 报告中的分数、解释、证据句之间有明确关系；
4. 页面在桌面端和移动端都不出现文本重叠；
5. 前端开发可以按本说明拆分组件。

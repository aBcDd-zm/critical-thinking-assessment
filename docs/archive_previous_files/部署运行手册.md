# 部署运行手册

本文档用于帮助团队成员从 Gitee 拉取项目，并在本地启动审辩式思维动态测评系统基线版。当前版本以本地开发部署为主，目标是让每位成员能够稳定启动后端、连接数据库、导入测评配置，并通过接口检查确认环境可用。

## 1. 当前部署目标

本阶段只要求跑通本地开发环境：

1. 能从 Gitee 拉取最新代码；
2. 能启动 MySQL 开发数据库；
3. 能创建 Python 虚拟环境并安装依赖；
4. 能执行数据库迁移和 seed 数据导入；
5. 能启动 FastAPI 后端；
6. 能访问 Swagger 和核心检查接口；
7. 能在无 DeepSeek API Key 的情况下通过 `mock` 模式运行。

当前不要求部署到公网服务器，也不要求配置生产环境。

## 2. 环境要求

建议所有成员优先使用 Windows + PowerShell。其他系统也可以运行，但命令需要按系统习惯微调。

| 工具 | 建议版本 | 用途 | 检查命令 |
| --- | --- | --- | --- |
| Git | 2.40+ | 拉取代码 | `git --version` |
| Python | 3.11 | 运行 FastAPI 后端 | `python --version` |
| Docker Desktop | 最新稳定版 | 启动统一 MySQL | `docker --version` |
| Docker Compose | Docker Desktop 自带 | 管理 MySQL 容器 | `docker compose version` |
| 浏览器 | Chrome / Edge | 访问 Swagger | 无 |

如果暂时没有 Docker，也可以使用本机 MySQL，但需要手动创建数据库并修改 `.env`，见本文档第 8 节。

### 2.1 macOS 环境准备

Apple Silicon Mac 推荐使用 Homebrew 安装 Python 3.11，并使用 Docker Desktop 运行项目 MySQL：

```bash
brew install python@3.11
brew install --cask docker
open -a Docker
```

首次打开 Docker Desktop 时需要完成系统授权并等待状态显示为可用。随后在仓库根目录执行：

```bash
docker compose up -d mysql
```

macOS 后端环境使用：

```bash
cd backend
/opt/homebrew/bin/python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

## 4. 快速启动流程

在仓库根目录执行：

```powershell
docker compose up -d mysql
```

进入后端目录：

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
copy .env.example .env
python -m alembic upgrade head
python scripts\seed_db.py
python scripts\check_db.py
python scripts\check_agent_contract.py

```

启动成功后，浏览器访问：

```text
http://127.0.0.1:8000/docs
```

如果 Swagger 页面能打开，说明后端服务已经启动。

## 5. 分步骤说明

### 5.1 启动 MySQL

在仓库根目录执行：

```powershell
docker compose up -d mysql
```

当前 Docker MySQL 配置：

| 配置项 | 值 |
| --- | --- |
| 容器名 | `psychological_assessment_mysql` |
| MySQL 版本 | `mysql:8.0` |
| 本机端口 | `3307` |
| 容器端口 | `3306` |
| 数据库名 | `psychological_assessment` |
| 用户名 | `root` |
| 密码 | `123456` |
| 字符集 | `utf8mb4` |

检查容器状态：

```powershell
docker compose ps
```

查看 MySQL 日志：

```powershell
docker compose logs mysql
```

### 5.2 创建 Python 虚拟环境

进入后端目录：

```powershell
cd backend
```

创建虚拟环境：

```powershell
python -m venv .venv
```

激活虚拟环境：

```powershell
.\.venv\Scripts\Activate.ps1
```

看到命令行前面出现 `(.venv)`，表示激活成功。

如果 PowerShell 不允许执行脚本，可临时执行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### 5.3 安装依赖

在 `backend` 目录执行：

```powershell
python -m pip install -r requirements.txt
```

主要依赖包括：

| 依赖 | 用途 |
| --- | --- |
| `fastapi` | 后端 Web 框架 |
| `uvicorn` | 本地 ASGI 服务 |
| `SQLAlchemy` | ORM |
| `alembic` | 数据库迁移 |
| `PyMySQL` | MySQL 驱动 |
| `pydantic-settings` | 环境变量配置 |
| `PyYAML` | 读取 seed 配置 |
| `httpx` | 调用 DeepSeek API |

### 5.4 创建本地配置文件

首次部署时复制环境变量模板：

```powershell
copy .env.example .env
```

如果本地已经存在 `.env`，不要直接覆盖。可以打开 `.env.example` 对照新增配置项，再手动补到自己的 `.env` 中。

默认 `.env.example` 已适配 Docker MySQL：

```env
DATABASE_URL=mysql+pymysql://root:123456@127.0.0.1:3307/psychological_assessment?charset=utf8mb4
MODEL_PROVIDER=deepseek
MODEL_GATEWAY_MODE=mock
DEEPSEEK_MODEL=deepseek-v4-pro
```

注意：

- `.env` 是本地私有配置，不提交到 Git；
- DeepSeek API Key 不写入仓库；
- 没有 API Key 时保持 `MODEL_GATEWAY_MODE=mock`。

### 5.5 执行数据库迁移

在 `backend` 目录执行：

```powershell
python -m alembic upgrade head
```

该命令会创建当前基线版需要的业务表，包括受测者、测评会话、情境配置、rubric、AgentTrace、评分和报告等表。

### 5.6 导入 seed 数据

在 `backend` 目录执行：

```powershell
python scripts\seed_db.py
```

当前 seed 包括：

| 文件 | 内容 |
| --- | --- |
| `seeds/rubric.yaml` | 六维能力评分初稿 |
| `seeds/scenario_product_48h.yaml` | 默认测评情境 |
| `seeds/scenario_pool.yaml` | 情境池 |
| `seeds/prompts.yaml` | Agent prompt 模板 |
| `seeds/report_template.yaml` | 报告模板 |

seed 脚本是 upsert 逻辑，重复执行不会重复插入同一批配置。

### 5.7 检查数据库与 Agent 契约

在 `backend` 目录执行：

```powershell
python scripts\check_db.py
python scripts\check_agent_contract.py
```

`check_db.py` 成功时会输出：

```text
Database check passed.
```

`check_agent_contract.py` 成功时会输出类似：

```text
Agent contract check passed: context_fields=13, outputs=4, seed={'dimensions': 6, 'stages': 6, 'dynamic_infos': 6, 'intervention_rules': 12}
```

所有成员开工前都需要先通过这两个检查。尤其是全栈 B / 全栈 C，后续 Agent 模块必须基于当前共享 schema 开发，不要另起一套输入输出结构。

如果提示缺表，通常是没有执行迁移，先重新执行：

```powershell
python -m alembic upgrade head
```

如果 `check_agent_contract.py` 失败，通常说明 seed 文件不完整、Agent schema 被改坏，或本地代码没有拉到最新版本。先执行：

```powershell
git pull origin master
python scripts\seed_db.py
python scripts\check_agent_contract.py
```

### 5.8 启动后端服务

在 `backend` 目录执行：

```powershell
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

启动成功后，访问：

```text
http://127.0.0.1:8000/docs
```

## 6. 部署成功检查

启动后端后，依次检查以下地址。

### 6.1 浏览器检查

| 地址 | 预期结果 |
| --- | --- |
| `http://127.0.0.1:8000/docs` | 能看到 Swagger 接口页面 |
| `http://127.0.0.1:8000/api/v1/health` | 返回 `{"status":"ok"}` |
| `http://127.0.0.1:8000/api/v1/health/db` | 返回数据库 connected |
| `http://127.0.0.1:8000/api/v1/scenarios/default` | 返回默认情境 |
| `http://127.0.0.1:8000/api/v1/model-gateway/status` | 返回模型网关状态 |

### 6.2 PowerShell 检查

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health/db
Invoke-RestMethod http://127.0.0.1:8000/api/v1/model-gateway/status
```

### 6.3 会话接口检查

```powershell
$body = @{
  nickname = "demo_user"
  info_collect_method = "ai_dialogue"
  assessment_mode = "mock"
} | ConvertTo-Json

Invoke-RestMethod `
  -Uri http://127.0.0.1:8000/api/v1/sessions `
  -Method POST `
  -ContentType "application/json" `
  -Body $body
```

成功时会返回 `session_uuid`、当前情境、当前阶段和第一条 AI 开场问题。

### 6.4 用户测评前端检查

启动前端：

```powershell
cd frontend
npm run dev
```

打开用户测评端：

```text
http://127.0.0.1:5173/assessment
```

当前前端最小闭环已经支持：

1. 输入昵称并创建测评会话；
2. 展示默认情境、当前阶段和 AI 开场问题；
3. 提交用户回答并刷新对话历史；
4. 结束测评并进入报告页；
5. 报告未生成时展示六维评分空状态。

测评对话页还支持浏览器原生语音转文字：点击输入框左侧麦克风并允许浏览器使用麦克风，语音会实时写入输入框，说完后自动提交给面试官；文字发送后输入框会立即清空，若提交失败才恢复原文。面试官的最新问题会自动朗读，也可以通过顶部“面试官朗读：开/关”控制。系统只提交确认后的文字，不保存音频。该能力依赖浏览器的语音识别与语音合成实现；Chrome / Edge 体验较完整，不支持时会自动提示改用文字输入。

### 6.5 无前端后端流程检查

前端页面尚未完成时，后端和 Agent 同学先用模拟用户数据做验收：

```powershell
cd backend
.\.venv\Scripts\python.exe scripts\check_agent_fixture_cases.py
.\.venv\Scripts\python.exe scripts\check_mock_assessment_flow.py
```

第一条命令检查假用户、对话样例和评分样例是否与 seed/rubric/schema 对齐；第二条命令会在本地创建一次模拟测评 session，写入一条假用户回答，并在检查后清理本次模拟数据。

### 6.6 后台会话复盘与研究数据导出

管理员登录后访问：

```text
http://127.0.0.1:5173/admin/sessions
```

该页面支持按状态、情境代码、昵称或 Session UUID 查询，并可进入单次会话查看完整对话、AgentTrace、评分证据、报告和反馈。

页面提供两种研究数据导出：

- JSON：保留完整嵌套结构；
- CSV ZIP：按会话、对话、Trace、评分、证据、报告和反馈拆分为多张 UTF-8 BOM CSV。

导出前必须在 `backend/.env` 中设置独立密钥：

```env
EXPORT_PSEUDONYM_SECRET=替换为随机且长期保存的密钥
```

同一密钥会为同一会话生成稳定的匿名编号。更换密钥会改变编号。导出会移除直接身份字段，但自由文本仍可能包含参与者主动输入的信息，因此属于去标识化研究数据，不等于绝对匿名数据。

验证接口和导出逻辑：

```bash
python scripts/check_admin_session_review.py
```

### 6.7 GitHub Actions 检查

仓库的 `.github/workflows/ci.yml` 会在 Pull Request、`main` 和 `system/**` 分支推送时运行：

1. Python 3.11 + MySQL 8 后端迁移、seed 和 Mock 验收脚本；
2. Node 22 前端依赖安装和生产构建；
3. 不调用需要密钥的真实 DeepSeek 检查。

如果只想检查 fixture 和 Agent schema，不连接数据库，可以运行：

```powershell
.\.venv\Scripts\python.exe scripts\check_mock_assessment_flow.py --skip-db
```

## 7. DeepSeek 模型网关配置

当前项目已经预留统一模型网关：

```text
GET  /api/v1/model-gateway/status
POST /api/v1/model-gateway/chat
```

默认配置是：

```env
MODEL_PROVIDER=deepseek
MODEL_GATEWAY_MODE=mock
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_ENABLE_THINKING=true
DEEPSEEK_REASONING_EFFORT=high
```

### 7.1 无 API Key 模式

大多数成员开发时保持：

```env
MODEL_GATEWAY_MODE=mock
```

这种模式不会真实请求 DeepSeek，适合：

- 部署检查；
- 前端页面开发；
- Agent 输入输出结构开发；
- 无网络或无 API Key 环境。

### 7.2 真实 DeepSeek 模式

需要真实调用 DeepSeek 时，在本地 `backend/.env` 修改：

```env
MODEL_GATEWAY_MODE=real
DEEPSEEK_API_KEY=你的 DeepSeek API Key
```

注意：

1. 不要把 API Key 写入 `.env.example`；
2. 不要把 API Key 发到公开群聊；
3. 不要提交 `.env`；
4. 如果真实模型调用不稳定，先切回 `mock` 保证开发流程不断。

全栈 B 验收 HostAgent / FollowupAgent 真实模型接入时，需要运行严格检查脚本：

```powershell
cd backend
$env:MODEL_GATEWAY_MODE="real"
$env:DEEPSEEK_API_KEY="你的 DeepSeek API Key"
.\.venv\Scripts\python.exe scripts\check_dialogue_agent_real_strict.py
Remove-Item Env:\DEEPSEEK_API_KEY
```

该脚本要求真实模型返回结构化 Host/Followup 输出，并且 `fallback_used=false`。如果模型调用失败后走了 fallback，脚本会判定失败，不能作为真实接入通过。

## 8. 不使用 Docker 的本地 MySQL 方案

如果本机没有 Docker，可以使用本地 MySQL。

### 8.1 创建数据库

登录本地 MySQL 后执行：

```sql
CREATE DATABASE IF NOT EXISTS psychological_assessment
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
```

### 8.2 修改 `.env`

把 `backend/.env` 中的 `DATABASE_URL` 改成自己的用户名、密码和端口：

```env
DATABASE_URL=mysql+pymysql://root:你的密码@127.0.0.1:3306/psychological_assessment?charset=utf8mb4
```

然后继续执行：

```powershell
python -m alembic upgrade head
python scripts\seed_db.py
python scripts\check_db.py
python scripts\check_agent_contract.py
```

## 9. 常见问题

### 9.1 `docker` 命令不存在

说明 Docker Desktop 没安装或没有启动。

处理方式：

1. 安装并启动 Docker Desktop；
2. 重新打开 PowerShell；
3. 执行 `docker --version` 检查。

### 9.2 MySQL 端口 `3307` 被占用

表现：

```text
port is already allocated
```

处理方式：

1. 检查是否已经启动过项目 MySQL：

   ```powershell
   docker compose ps
   ```

2. 如果是其他程序占用，修改 `docker-compose.yml` 里的端口映射，例如：

   ```yaml
   ports:
     - "3308:3306"
   ```

3. 同步修改 `backend/.env`：

   ```env
   DATABASE_URL=mysql+pymysql://root:123456@127.0.0.1:3308/psychological_assessment?charset=utf8mb4
   ```

### 9.3 后端端口 `8000` 被占用

换一个端口启动：

```powershell
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
```

对应访问：

```text
http://127.0.0.1:8001/docs
```

### 9.4 `ModuleNotFoundError`

通常是虚拟环境没有激活，或依赖没有安装。

处理方式：

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### 9.5 `alembic` 命令找不到

优先使用：

```powershell
python -m alembic upgrade head
```

这比直接执行 `alembic upgrade head` 更稳定。

### 9.6 数据库连接失败

先检查 MySQL 是否启动：

```powershell
docker compose ps
```

再检查 `.env` 的 `DATABASE_URL` 是否和实际端口、密码一致。

Docker 默认应为：

```env
DATABASE_URL=mysql+pymysql://root:123456@127.0.0.1:3307/psychological_assessment?charset=utf8mb4
```

### 9.7 seed 导入失败

优先检查：

1. 是否已经执行 `python -m alembic upgrade head`；
2. `backend/seeds/` 下 YAML 文件是否存在；
3. 终端是否在 `backend` 目录。

可以先做 dry-run：

```powershell
python scripts\seed_db.py --dry-run
```

### 9.8 中文显示乱码

如果 PowerShell 直接打印中文 JSON 出现乱码，但浏览器或前端显示正常，通常是终端编码问题。

可以先执行：

```powershell
chcp 65001
```

然后重新运行检查命令。

### 9.9 想重建本地 Docker 数据库

只有在确认本地数据可以删除时再执行：

```powershell
docker compose down -v
docker compose up -d mysql
cd backend
python -m alembic upgrade head
python scripts\seed_db.py
python scripts\check_db.py
python scripts\check_agent_contract.py
```

`docker compose down -v` 会删除 Docker volume 中的本地数据库数据。

# Demo 2.0 数字面试官前端交互设计

> **版本：主流程交互修订版。** 本版在原型实验结论基础上，补充“消息式入场 + 情境资料沉淀到右侧资料板”的主流程交互，用于解决访谈板块和情境板块信息重复的问题。

## 1. 设计目标

把当前的"聊天式测评页面"升级为"数字面试官式访谈体验"。核心原则：用户进入页面后的第一感受是"这位面试官在和我交流"，而不是"我在填一份网页问卷"。

## 2. 设计理念

### 2.1 极简黑白线条风格

数字面试官采用**纯 SVG 手绘线条**风格——黑色线条、白色背景、无填充色块、无渐变色。

**为什么是这个画风。** 我们调研了以下开源项目并在原型中做了验证：

| 项目 | 我们能用的 | 证明行不通的 |
|---|---|---|
| **Comicode**（开源火柴人框架） | 角色类型 + 表情 + 姿势的枚举思路。11 表情 × 12 姿势的设计维度可参考 | AI 生成复杂 SVG 人物不可靠。作者明确写下："AI 无法可靠处理人体曲线和有机运动。即使是简单火柴人，姿势空间也接近无限，不可能通过枚举达到自然效果" |
| **Zuki React**（React 动画角色） | 单组件 + 多动画状态的架构正确。props 驱动状态切换可借鉴 | 依赖 React CSS keyframe 的组合方式对 Vue 移植有成本。纯 CSS 方案更轻 |
| **Sticky Jo**（MediaPipe 骨骼检测 + SVG 渲染） | 骨骼检测的思路对将来语音+表情联动有参考价值 | 依赖 MediaPipe 和 Canvas，对当前需求过重 |

**最终方案。** 纯黑线 SVG 火柴人。头部圆形 + 直线身体 + Q 弧线四肢。四表情只靠三个 SVG 元素（眼睛的 rx/ry、眉毛的 path d、嘴巴的 path d），每表情约 8 行 CSS。这是人类和 AI 都能稳定维护的复杂度。抽象度刚好——用户视其为人，但不挑剔画得是否逼真。

### 2.2 SVG 火柴人技术细节

**数据结构。** 火柴人是单一 SVG 文件（viewBox 144×200），五官是带 class 的三个元素：

```html
<ellipse class="s-eye eye-l" cx="58" cy="56" rx="3.5" ry="3.5" />
<ellipse class="s-eye eye-r" cx="86" cy="56" rx="3.5" ry="3.5" />
<path class="s-mouth mouth" d="M64 72 Q72 78 80 72" />
<path class="s-brow brow-l" d="M50 47 Q56 44 62 48" />
<path class="s-brow brow-r" d="M82 48 Q88 44 94 47" />
```

**头身比。** 头 r=28（直径 56），脸中心 y=56，脸底 y=84。眼睛在 y=56、嘴在 y=72——全在脸范围内。身体高约 68 像素。手臂从 y=118 斜向下到桌面。

**表情切换。** CSS class 控制，不换 SVG 文件：

| 状态 | 眼睛 | 嘴 | 眉 | 触发 |
|---|---|---|---|---|
| `calm` | 圆点 rx=3.5 | 浅笑 M64→72→80 arc | 平直 | 默认等待 |
| `thinking` | 缩小 rx=2 | 小点 M69→72→75 | 内端下压 | AI 分析中 + 头顶三跳点 |
| `speaking` | 放大 rx=4,ry=5 | 张嘴 M62→72→82 arc | 微扬 | TTS 播放中 |
| `pleased` | 眯线 ry=1.5 | 大笑 M62→72→82 arc | 上扬 | 用户长回答后 2s |

切换用 `transition: all 0.35s ease`，平滑动效。不涉及 DOM 增删。

### 2.3 场景元素

**角色。** 圆形头 + 三缕头发 + 耳朵 + 圆领 + 直线身体 + 弧线双臂（左手放在桌面有手指，右手微举做手势）+ 双腿 + 椭圆鞋。

**椅子。** 灰色虚框在角色身后，表示角色是坐着面试的。

**桌面。** 黑色粗线桌面 + 白色面板。物品：笔记本电脑、咖啡杯、便签纸、桌牌、小盆栽——全部纯线条轮廓 SVG，用 `stroke="#1a1a1a"` 统一。

**关键经验。** 桌面物品的细节线条用 `stroke="#d0d0d0"` 而非纯黑——这创造了"远景/近景"的视觉层次，让角色主体的黑色线条更突出。

### 2.4 布局：上下分栏

整体采用上下堆叠布局——上方是面试官场景，下方是对话区域。这个布局让角色始终在用户视野上方，更像"面试官坐在对面"的第一人称感。

```
+------------------------------------------------------------------+
|                          [轻量顶栏]                                |
|   退出测评 | 主题 3/6 · 证据评估                        25:12      |
+------------------------------------------------------------------+
|                                                                    |
|                    [数字面试官场景区域]                              |
|                                                                    |
|    墙面 + 窗户背景 + 书架 + 挂钟                                    |
|                                                                    |
|              ┌──────────────────┐                                  |
|              │    火柴人角色     │  ← 面试官坐在桌对面，面向用户      |
|              │  (表情 + 椅子)   │                                  |
|              └──────────────────┘                                  |
|                      状态标签                                       |
|                  "我在听你说"                                       |
|                                                                    |
|     ═══════════════════════════════  ← 大桌面（近景，横贯画面）     |
|     💻   📝   ☕     📱  🖊       ← 桌上的物品（笔记本电脑、便签等） |
|                                                                    |
+------------------------------------------------------------------+
|                                                                    |
|                      [对话区域]                                     |
|                                                                    |
|    ┌──────────────────────────────────────┐                       |
|    │ 面试官：你先按自己的理解说说...        │ ← 聊天气泡             |
|    └──────────────────────────────────────┘                       |
|                                                                    |
|    ┌──────────────────────────────────────┐                       |
|    │ 我：我觉得最核心的问题是...           │ ← 用户气泡             |
|    └──────────────────────────────────────┘                       |
|                                                                    |
+------------------------------------------------------------------+
|                                                                    |
|                     [输入区域]                                      |
|                                                                    |
|    [🎤]  [________________________] [发送]  [结束测评]              |
|                                                                    |
+------------------------------------------------------------------+
```

场景区和对话区的高度比例建议为 **场景区约 45% · 对话区约 55%**（桌面端）。场景区至少保留 340px 高度以保证桌子、角色和背景墙的视觉完整性。对话区自动撑满剩余空间，输入栏固定在底部。

响应式断点：960px 以下场景区缩小到约 280px，540px 以下精简场景元素（隐藏书架和挂钟，缩小角色 SVG）。

## 4. 对话交互

### 4.1 聊天气泡

保持现有原型的设计——AI 左对齐浅灰（`#f5f5f5`）、用户右对齐微暖（`#faf8f5`）。AI 消息出现时带打字机或流式效果。追问类型用小标签标注："开场"、"追问"、"新信息"。

对话区只长期保留真正的访谈内容：打招呼、当前问题、AI 追问、动态信息提示、用户回答和阶段过渡。完整情境背景、阶段说明这类资料型内容不长期占用对话区，避免和右侧资料板重复。

### 4.2 入场消息队列

进入测评页后，系统不应一次性把大段情境文本塞进一个气泡，也不应一开始就把右侧资料板铺满。推荐采用“面试官逐条发消息”的入场方式，让用户像收到真实面试官消息一样逐步进入情境。

入场消息建议拆成四类：

| 消息类型 | 是否长期保留在访谈区 | 作用 |
|---|---|---|
| `greeting` | 保留 | 建立关系，例如“你好，我是本次测评的 AI 面试官。” |
| `scenario_intro` | 播放后淡出 | 用口语化方式介绍情境背景 |
| `stage_intro` | 播放后淡出 | 说明当前阶段要讨论什么 |
| `current_question` | 保留 | 抛出用户当前需要回答的问题 |

推荐播放节奏：

```text
页面进入
-> 面试官状态 calm/listening
-> greeting 气泡出现
-> scenario_intro 气泡逐条出现
-> stage_intro 气泡逐条出现
-> 资料型气泡短暂停留 600-1000ms
-> scenario_intro / stage_intro 淡出并收起
-> 右侧 ScenarioPanel 滑入，承接完整情境与阶段信息
-> current_question 保留在访谈区
-> 输入栏进入可回答状态
```

注意：这里的“消失”只是前端视觉处理，不代表数据库删除。用户实际看到过的情境、阶段说明和 AI 可见文本仍应保存在 `DialogueTurn` 或对应前端状态中，方便后续报告、回放和后台分析。

### 4.3 情境资料板

右侧不再叫“情境卡片”，而是作为“资料板 / 案例板”存在。它的职责是承载结构化资料，方便用户在回答时随时回看。

资料板展示内容：

1. 情境标题；
2. 情境背景；
3. 当前阶段说明；
4. 当前问题原文；
5. 已释放的动态信息；
6. 当前阶段进度和追问次数。

资料板出现时机：

1. 首次进入页面时先隐藏或弱化；
2. 入场消息里的 `scenario_intro` 和 `stage_intro` 播放完成后，从右侧滑入；
3. 后续释放动态信息时，对话区先给出简短提示，资料板新增一条“已释放信息”；
4. 阶段切换时，资料板内容更新，并用轻量过渡提示用户已经进入新阶段。

这样可以形成清晰分工：

| 区域 | 职责 |
|---|---|
| 访谈区 | 像聊天一样推进交流，收集用户表达 |
| 资料板 | 保存情境、阶段和动态信息，供用户回看 |

### 4.4 资料消息转场动画

资料型消息从访谈区沉淀到资料板时，建议使用轻量动画，避免页面显得突兀：

1. 资料型气泡完成打字机效果后，停留 600-1000ms；
2. 气泡透明度降到 0，最大高度折叠到 0；
3. 右侧资料板从 `translateX(16px)` 到 `translateX(0)`，透明度从 0 到 1；
4. 资料板内对应段落做一次 300ms 的浅色高亮，提示“这条信息已经被归档到资料板”；
5. 动画总时长控制在 500-800ms，不能影响用户开始回答。

动效原则：

- 动画服务信息结构，不做炫技；
- 不重复播放已经归档的资料型气泡；
- 用户刷新页面或回到已有 session 时，不重新播放入场转场，直接展示稳定状态；
- 流式输出结束后，不再额外触发一次打字机重放。

### 4.5 角色状态联动

| 用户动作 | 角色状态 | 标签文字 |
|---|---|---|
| 页面空闲 | `calm` | 我在听你说 |
| 提交回答后 | `thinking` + 头顶三跳点 | 让我想想... |
| AI 输出文字 | `speaking` | 面试官正在说... |
| 用户长回答后 | `pleased`（2 秒后回 calm） | 说得很好 |
| 阶段切换 | `nod` 动画 0.4s | 短暂过渡 |

### 4.6 动态信息呈现

当 AI 输出动态信息时，不建议把完整资料长期留在访谈区。推荐做法：

1. 访谈区显示一条自然语言提示，例如“我补充一条新信息，你可以结合它再想想。”；
2. 资料板新增完整动态信息卡片；
3. 当前问题或追问保留在访谈区；
4. 该动态信息需要在后台与 `DialogueTurn.dynamic_info_id`、`AgentTrace.selected_dynamic_info_id` 对齐，保证用户实际看到的内容可追溯。

### 4.7 前端状态建议

为实现上述效果，前端可在渲染层维护一组展示状态，不要求后端立刻改变原始数据结构：

```ts
type DisplayMessageRole = "persistent" | "ephemeral_context";

interface DisplayMessage {
  id: string;
  sourceTurnIndex?: number;
  type: "greeting" | "scenario_intro" | "stage_intro" | "current_question" | "followup" | "dynamic_info";
  role: DisplayMessageRole;
  content: string;
  status: "queued" | "typing" | "visible" | "archiving" | "archived";
}
```

其中 `ephemeral_context` 表示“播放后归档到资料板”的资料型消息。它只影响前端显示，不改变后端对话记录。

## 5. 语音交互

P0：浏览器 Web Speech API。`SpeechRecognition` 做 STT，`SpeechSynthesis` 做 TTS。麦克风按钮带脉动圆环动画，录音 3 秒后自动转写。

P1：接入百度/阿里 TTS 流式接口提升品质。

**兜底。** 语音功能始终是体验增强，失败不阻断文字流程。

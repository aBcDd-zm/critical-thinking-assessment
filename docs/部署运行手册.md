# 部署运行手册（云服务器 Docker 版）

> 适用：将本系统整体部署到一台公网云服务器（阿里云/腾讯云 ECS 等）。
> 架构：`frontend`（Nginx 托管 Vue 构建产物 + 反代 `/api`，**只监听 127.0.0.1:8080**）→ `backend`（FastAPI/uvicorn）→ `mysql`（仅 compose 内网可达）。
> 公网流量由宿主机既有 Nginx/宝塔面板站点反向代理到 `127.0.0.1:8080`（见第六节）；若服务器专用、无其他站点，也可把 compose 中 frontend 端口改回 `"80:80"` 直连。
> 前端构建时 `VITE_API_BASE_URL=/api/v1`，同源反代，无跨域问题；流式对话接口已在容器 Nginx 关闭代理缓冲。

## 一、服务器准备（一次性）

```bash
# 1. 安装 Docker（官方脚本，含 compose 插件）
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 2. 获取代码
git clone https://github.com/aBcDd-zm/critical-thinking-assessment.git
cd critical-thinking-assessment
```

云厂商安全组需放行入方向 **80**（启用 HTTPS 后再放行 **443**）。3306/3307/8000 一律不要对公网开放。

## 二、配置

```bash
cp .env.production.example .env.production
vim .env.production
```

必改四项：

| 变量 | 说明 |
| --- | --- |
| `MYSQL_ROOT_PASSWORD` | 数据库强密码（compose 自动拼进 `DATABASE_URL`） |
| `DEEPSEEK_API_KEY` | 真实密钥；公网可被任何访客发起测评消耗额度，务必关注用量与限额 |
| `ADMIN_PASSWORD` | 管理后台强密码 |
| `ADMIN_TOKEN_SECRET` | ≥32 位随机串（`openssl rand -hex 32`） |

`BACKEND_CORS_ORIGINS` 换成你的公网地址（同源部署下仅兜底用）。

Humanistic Interviewer v1 / v1.1 默认关闭，生产模板必须保持：

```dotenv
INTERVIEWER_STYLE_ENABLED=false
INTERVIEWER_STYLE_DEFAULT=baseline_v1
INTERVIEWER_RENDER_TIMEOUT_SECONDS=3
```

v1 只有完成 [离线 A/B 与发布门禁](humanistic_interviewer/offline_ab_evaluation_v1.md)、
[10–20 次内部 UAT](humanistic_interviewer/internal_uat_template_v1.md)，并由成员 A/B
共同审核后，才可在受控环境把前两项临时改为 `true` 和 `humanistic_v1`。
v1.1 必须另行满足
[v1.1 独立门禁与成员 A 测量批准](humanistic_interviewer/humanistic_interviewer_v1_1_implementation.md)，
旧 v1 的证据或 PASS 不能继承；当前状态见
[v1.1 验收报告](humanistic_interviewer/acceptance_report_v1_1.md)。
该设置只给新建的 `progressive_v3_3` 会话冻结 Humanistic 版本，公开测评 API
和被试端没有风格选择入口。

## 三、启动

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build

# 初始化数据库（首次，以及每次升级后）
docker compose --env-file .env.production -f docker-compose.prod.yml exec backend alembic upgrade head
docker compose --env-file .env.production -f docker-compose.prod.yml exec backend python scripts/seed_db.py
```

## 四、验证

```bash
curl http://127.0.0.1:8080/api/v1/health          # {"status":"ok"}
curl http://127.0.0.1:8080/api/v1/health/db       # database connected
curl http://127.0.0.1:8080/api/v1/model-gateway/status
```

配好第六节的反代后，浏览器访问 `http://<域名或IP>/assessment` 完整走一遍测评（real 模式消耗 DeepSeek 额度）；`/admin/login` 登录管理后台。

## 五、日常运维

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml logs -f backend    # 看后端日志
docker compose --env-file .env.production -f docker-compose.prod.yml restart backend    # 重启单个服务
docker compose --env-file .env.production -f docker-compose.prod.yml down               # 停止（数据卷保留）

# 升级到新版本
git pull
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
docker compose --env-file .env.production -f docker-compose.prod.yml exec backend alembic upgrade head
docker compose --env-file .env.production -f docker-compose.prod.yml exec backend python scripts/seed_db.py

# 数据库备份
docker compose --env-file .env.production -f docker-compose.prod.yml exec mysql \
  sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" psychological_assessment' > backup_$(date +%F).sql
```

### Humanistic v1 / v1.1 受控启用与一键回退

启用前必须先执行迁移与 seed，确保
目标 Prompt（`humanistic_interviewer_compact_v1` 或
`humanistic_compact_v1_1`）已按 `template_code + version` 精确写入数据库。
v1.1 的建议运行时配置为：

```dotenv
RUNTIME_CONSULTATIVE_TURN_TIMEOUT_SECONDS=8
RUNTIME_INTERVIEWER_RENDER_TIMEOUT_SECONDS=5
RUNTIME_HUMANISTIC_V11_MODEL_POLISH_MODE=adaptive
```

其中正式追问、事件、整合、低信息和理解失败回合最多进行一次有上下文的
模型表达，其余非测量路由保持确定性；不要通过改为 `always` 或放大超时
来追求人本感。若要回退，仍以总开关为准。
修改
`.env.production` 后仅重建 backend：

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --force-recreate backend
```

紧急回退时将 `INTERVIEWER_STYLE_ENABLED=false`，再次执行同一条命令。总开关是
运行时 kill switch：关闭后，包括已冻结为 `humanistic_v1` 的进行中会话，也会立即使用
baseline 表达；数据库中保留原冻结版本和 configured/applied 审计字段，重新打开才恢复。
不要通过修改会话数据做回退。

每次启用或回退后，在管理端抽查：

- 会话的 `interviewer_style_version`；
- `consultative_turn` 与 `interviewer_renderer` 的父子 Trace；
- 实际 Prompt ID、`model_attempt_count`、校验码与 fallback 原因；
- 总响应 p95、Renderer 兜底率以及零容忍错误计数。

当前门禁状态以
[Humanistic v1 验收报告](humanistic_interviewer/acceptance_report_v1.md)及
[Humanistic v1.1 验收报告](humanistic_interviewer/acceptance_report_v1_1.md)
为准；目标版本报告为 `BLOCKED` 时不得切换生产默认值。

## 六、宝塔/宿主 Nginx 前置反代（与其他站点共存）

宝塔面板 → 网站 → 添加站点（域名或用 IP 便捷访问）→ 设置 → 反向代理：

- 目标 URL：`http://127.0.0.1:8080`
- 发送域名：`$host`

**关键**：反代创建后编辑其配置文件，在 `location /` 中加入以下三行，否则流式对话会整段卡住不出字：

```nginx
proxy_buffering off;
proxy_http_version 1.1;
proxy_read_timeout 300s;
```

HTTPS：有域名时直接用宝塔站点的「SSL」页签一键申请 Let's Encrypt 证书即可，无需额外组件。

## 七、安全注意事项

- `.env.production` 已被 `.gitignore` 排除，任何情况下不得提交仓库；
- MySQL 与 backend 均未映射宿主端口，仅 80/443 对外；
- 公网开放意味着任何人可发起测评并消耗 DeepSeek 额度：比赛演示期之外建议关站（`down`）或在 DeepSeek 控制台设置额度上限；
- 管理后台默认账号必须改密后再上线。

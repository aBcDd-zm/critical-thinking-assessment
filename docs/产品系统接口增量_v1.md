# 产品系统接口增量 v1

## 2026-07-17：职业背景动态情景准备

### 创建会话

`POST /api/v1/sessions` 新请求示例：

```json
{
  "nickname": "小林",
  "occupation_category": "教育培训",
  "occupation": "高中生物教师"
}
```

`occupation_category` 必须为系统固定职业大类，`occupation` 长度为 2–64 字。新会话返回 `phase=onboarding`，并异步准备职业基础情景。

### 背景访谈流

`POST /api/v1/sessions/{session_uuid}/profile/turns/stream`

```json
{ "content": "我经常设计课堂活动，并根据学生反馈调整安排。" }
```

NDJSON 事件包括 `profile_answer_saved`、`profile_agent_started`、`profile_agent_completed`、`profile_completed` 和 `error`。

### 准备状态

`GET /api/v1/sessions/{session_uuid}/preparation` 返回：

- `phase`：`onboarding`、`scenario_preparing`、`assessment`、`completed`；
- `onboarding`：问题数、上限和完成状态；
- `scenario_preparation`：生成状态、缓存命中和通用情景降级状态；
- `assessment_ready`：是否可进入正式六阶段测评。

完整实现和研究隔离规则见 [V2.0 职业背景动态情景 Agent 实现说明](./职业背景动态情景Agent实现说明_v2.md)。

本文档记录 2026-07-17 B 侧收尾中新增或调整的公开接口语义。完整的历史基线合同仍保存在 `docs/archive_previous_files/api_contract_v1.md`；本次不修改主问题、追问、评分和证据选择契约。

## 1. 查询反馈状态

```http
GET /api/v1/sessions/{session_uuid}/feedback
```

成功响应统一使用 `FeedbackStateResponse`：

```json
{
  "session_uuid": "0ddedcc2-e688-45ee-8a27-736019e8e249",
  "submitted": false,
  "feedback": null
}
```

- 会话存在但尚未提交反馈：返回 `200`，`submitted=false`，`feedback=null`。
- 已提交反馈：返回 `200`，`submitted=true`，`feedback` 为原 `FeedbackResponse`。
- 会话不存在：返回 `404`。

`POST /api/v1/sessions/{session_uuid}/feedback` 的请求和响应结构保持不变；再次提交会更新同一会话的反馈。

## 2. 下载正式 PDF 报告

```http
GET /api/v1/sessions/{session_uuid}/report.pdf
```

成功时返回：

```text
Content-Type: application/pdf
Content-Disposition: attachment; filename*=UTF-8''...
Cache-Control: no-store
```

生成规则：

- 只读取已经保存的结构化报告，不再次调用模型。
- PDF 按需在内存中生成，不写入数据库、对象存储或仓库目录。
- 使用项目随附并带许可证的 Noto Sans SC 字体，支持中文检索和复制。
- 包含受测者、情境、总体结论、六维结果、反馈、优势、建议、发展计划和免责声明。
- 每个维度最多放入两条证据，每条最多约 220 字；被截断时标记“节选”。网页报告仍显示完整原话。
- 报告或会话不存在时返回 `404`；生成异常返回不暴露内部细节的 `500`。

浏览器前端使用 Blob 下载该文件，因此不会出现浏览器打印功能自动添加的本地地址、日期等页眉页脚。

## 3. 前端状态语义

- 页面产品称谓统一为“审辩式思维动态测评”。
- `completed`、`high`、`medium`、`low` 等存储值在界面映射为中文，不更改后端枚举。
- 反馈读取和报告读取相互独立；只有报告本身不存在时才显示“报告未生成”。
- 网页证据保留完整文本，默认四行折叠，可选择“展开原文”或“收起”。

## 4. 本地验证

```bash
cd backend
python scripts/check_feedback_state.py
python scripts/check_report_pdf_export.py

cd ../frontend
npm run test
npm run build
```

PDF 检查脚本会验证关键中文文本、六个维度、IE 维度、长证据节选和禁用文本，并生成仅供本地视觉检查的临时文件。检查结束后不应提交 `tmp/pdfs/`。

## 2026-07-21：渐进式访谈 v3

新建会话默认持久化 `flow_version=progressive_v3`；迁移前会话固定为 `legacy_v2`。环境变量 `INTERVIEW_FLOW_VERSION` 只影响后续新建会话，不改写进行中会话。

`POST /api/v1/sessions/{session_uuid}/turns` 和 `/turns/stream` 的请求增加：

```json
{
  "content": "我会先核实信息来源。",
  "content_type": "scenario_answer",
  "client_turn_id": "1c2a3d7e-e01b-4b31-9ec0-c04e7f4cc611",
  "answer_duration_ms": 12800
}
```

- `client_turn_id` 在会话内唯一；重试必须复用同一值。已完成请求重放已保存的 AI turn，不重复释放事件。
- `answer_duration_ms` 可选，只记录本次原始回答耗时。
- 流事件名称保持不变；`user_turn_saved`、`agent_delta` 和 `agent_completed` 增加 `replayed` 布尔值。

v3 `SessionResponse` 增加 `flow_version` 和模糊 `interview_progress`：

```json
{
  "flow_version": "progressive_v3",
  "current_stage": null,
  "progress": null,
  "interview_progress": {
    "formal_answer_count": 4,
    "target_min_answers": 9,
    "target_max_answers": 12,
    "percent": 33,
    "estimated_remaining_minutes": 10
  }
}
```

受测端不返回隐藏节点、未释放事件、证据槽位、Planner JSON 或证据分析。`legacy_v2` 继续返回原 `current_stage` 和 `progress`。

管理复核接口增加 `progressive_audit`，包含蓝图、结构指纹、当前槽位、证据时间线、Planner 决策和已释放事件。Agent Trace 增加 `fallback_type` 和 `prompt_template_id`；匿名导出同步带出 Planner 和 evidence-delta 字段，不导出职业具体描述或背景访谈原文。

## 2026-07-21：咨询式渐进访谈 v3.1

创建会话必须提交当前版本的明确知情同意：

```json
{
  "nickname": "小林",
  "occupation_category": "教育培训",
  "occupation": "高中生物教师",
  "consent_accepted": true,
  "consent_version": "critical_thinking_assessment_consent_v1"
}
```

缺少同意、值不为 `true` 或版本不匹配时返回 `422`，且不创建参与者、会话或情景生成任务。同意记录按会话保存版本、时间和授权范围。

公开会话与流式响应结构不变。内部 Planner 合同增加 `delivery_mode`；`RELEASE_EVENT` 同时记录 `release_unit_code`。完整场景事实保存在蓝图中，受测端每轮最多看到一个已验证的 `presentation_unit`，不会收到隐藏单元、当前维度或证据缺口。

Interviewer 可见文本执行以下约束：最多两句、90 个汉字和一个问号；反映内容必须引用指定用户 turn；不使用评价性表扬，不猜测情绪、人格或动机。新 Prompt 版本为 `progressive_planner_v3_1` 和 `progressive_interviewer_v3_1`，旧会话继续按其已保存版本和文本恢复。

## 2026-07-22：咨询式逐轮生成 v3.2

新建会话默认持久化 `flow_version=progressive_v3_2`。画像完成后使用确定性身份规则物化 `occupation_interview_skeleton_v3_2`，不创建 `ScenarioGenerationJob`，也不调用场景设计、审查或适配模型。`progressive_v3` 和 `legacy_v2` 会话仍走原版本链路。

画像完成后，`SessionResponse.phase` 进入 `opening_pending`，`scenario_preparation.status` 为 `skeleton_ready`。前端应立即调用：

```text
POST /api/v1/sessions/{session_uuid}/interview/start/stream
```

- 首次调用生成、校验并保存 `interview_opening`，然后从已保存文本发送 `agent_delta` 和 `agent_completed`。
- 已有开场时原样重放，事件携带 `replayed=true`；不新增 DialogueTurn 或 AgentTrace。
- 进入 `assessment` 后继续使用原幂等 `client_turn_id` 提交接口。

v3.2 每个正式回答最多调用一次模型，Agent Trace 统一记为 `agent_name=consultative_turn`，Prompt 版本为 `consultative_turn_v3_2`。Trace 同时保存身份约束、任务域、隐藏目标、证据 delta、Planner 动作、事实代码、用户可见话术、校验结果、模型、耗时与 fallback。单次模型硬超时默认为 8 秒；超时或格式/质量失败时直接使用确定性中性话术，不进行第二次模型修复。

## 2026-07-23：自然对话与证据充分度 v3.3

新建会话默认使用 `progressive_v3_3` 和 `occupation_interview_skeleton_v3_3`。骨架显式保存当前安排、新安排、小范围试用、进度与质量两方诉求及待作决定；旧 `progressive_v3_2` 和 `legacy_v2` 会话不改写。

确定性路由优先识别 `request_context` 和 `conversation_repair`。用户询问“眼下什么情况”“新旧安排是什么”或指出重复时，系统直接补全已知情境并换用新问题；这些 turn 的 `formal_answer=false`，不进入能力证据。`InterviewerOutput.reflection_source_quotes` 保存来源 turn ID 和逐字原文，质量门允许自然转述，但拒绝无来源观点、情绪或人格推断。

`ScoreResult.evidence_sufficiency_index` 为可空的 0–100 整数。它是项目定义的证据充分度（ESI），不与 legacy `confidence` 混用，也不表示能力结论正确概率。公开维度报告增加 `evidence_sufficiency_index`、`evidence_sufficiency_level`、`score_kind` 和说明；完全未观察为 `null/unobserved`。报告顶层 `measurement_quality` 保存技术失败率、总 fallback 率、缺失事件、有效性状态和重测建议。技术失败率不低于 30%、总 fallback 率不低于 50%，或系统问题导致反证/整合缺失时标记 `invalid`。
